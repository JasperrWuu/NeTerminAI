# 架构概览

NeTerminAI 采用 Tauri 模块化单体架构。

```text
React UI → Tauri Commands / Events → Rust Application Core → PTY / Telnet / Serial / Storage
```

## 约束

- React 负责界面和交互呈现，不管理系统进程。
- Rust 是会话状态的唯一可信来源。
- 高频终端输出不进入 React 全局状态。
- Tauri 命令保持轻薄，只负责校验、调用和结果转换。
- AI 未来只能提交结构化动作，不能绕过策略层直接写入 PTY。

## 连接生命周期

本地终端、Telnet 与串口都遵循 `Connecting → Connected → Closed` 状态边界。创建命令先为会话 ID 建立连接占位，再把阻塞工作交给后台线程；关闭标签会设置该次连接专属的取消标记。读取线程结束时只能清理持有同一标记的当前实例，旧任务不能误删后续重建的会话。

写入按会话顺序串行化，终端输出不经过 React 全局状态，而是在视图层按动画帧合并。尺寸同步和关闭属于后台维护操作，其竞态错误会被本地收口；连接、认证和用户输入错误仍会明确显示在对应终端中。

## AI 上下文基础

AI 上下文是一个独立的只读消费者，通过工作区当前活动分区和会话注册表按需获取终端快照。快照只使用 xterm 的公开 buffer API，包含运行时身份、连接状态、终端尺寸和有限的最新输出，可选包含用户当前选择；它不读取 DOM、不依赖 React 焦点或 xterm 私有字段，也不会写入设置、会话库或持续监听输出流。每次重连都会使用新的 sessionId，旧运行时的上下文不会覆盖新运行时。

快照带有固定版本和明确的行数、字符数上限。连接元数据只保留本地 Shell、Telnet 主机/端口或串口名称/波特率，不包含用户名、密码、终端输入或其他凭据。当前提供活动会话和可见分区的上下文读取能力，但本阶段不包含模型、供应商 SDK、提示词编排或 Agent 执行。

AI 侧栏的上下文范围属于当前 Assistant 运行时状态，不写入全局设置。用户可以选择活动会话、可见会话或手动勾选任意仍打开的会话；选择依据是 tabId，采集时再解析当前 sessionId，因此重连不会继续引用旧运行时，关闭标签也会自动移出范围。选择与 Tile 布局相互独立，隐藏但仍打开的标签仍可被明确选中。

多会话数据经过轻量规范化后按 SessionContextMemory 分开维护，再组装成带有 `tabId`、`sessionId`、标题和连接类型的结构化会话数组。每个会话的摘要、重要事实和近期事件都有上限，最新终端输出与压缩记忆分开保存；没有 AI Provider 时仍使用确定性的整理逻辑。分析结果中的命令提案必须携带目标会话，并在用户明确批准后通过当前运行时的 InputPump 发送，执行前再次校验 sessionId，过期提案会被拒绝。

## AI Runtime

AI 助手每次发送问题都会重新采集当前选择的会话，保留有界的对话历史，并将每个 Session 独立标记为 `SESSION CONTEXT / TERMINAL OUTPUT`。`ApiAiProvider` 使用 OpenAI-compatible HTTP API，支持流式 SSE、取消和超时；`ProcessAiProvider` 通过独立的 Rust `AiProcessRunner` 调用用户明确配置的 CLI 或 PowerShell 脚本，stdin 传入结构化请求，stdout 与 stderr 分离。AI 进程不复用终端 PTY、xterm 或 Session worker，因此供应商故障、停止生成和进程错误都不会影响终端连接。

API Key 只存在于当前运行内存，绝不写入 localStorage、ApplicationSettings 或日志。命令提案始终先显示在 AI 侧栏，只有用户点击“运行”后才会经由 `TerminalActionExecutor → TerminalSessionRegistry → InputPump` 发送；AI 不能自行改变目标会话、可执行文件或脚本路径。Claude CLI、OpenCode CLI、PowerShell 和自定义 CLI 使用同一进程边界，具体命令参数与本机环境需在手工验收时确认。

## 本地终端链路

```text
xterm.js → Tauri command → TerminalManager → portable-pty → PowerShell
PowerShell → PTY reader thread → Tauri event → xterm.js
```

PTY 输出以 Base64 编码的原始字节块传输。界面层使用流式 UTF-8 解码器保留跨数据块字符边界，再由会话级文字着色流保留当前可见行的有限上下文，最后交给 xterm.js 完成终端字符解析和绘制。这样即使 Telnet 把远端回显拆成单字符数据块，跨块匹配规则仍然能够生效，同时不会为了等待完整单词而延迟终端输入。

## Telnet 链路

TelnetManager 将连接建立、读取、顺序写入和关闭分离。协议状态机负责 IAC 协商并抑制重复响应；终端输出按显示帧合并后交给 xterm.js，避免高吞吐连接用大量小事件阻塞界面。关闭正在建立的连接会立刻标记取消，后续得到的套接字不会进入活动会话。

保存会话与运行中连接相互独立。会话库保存连接资料、登录模式和用户分区；工作区标签持有一次连接所需的快照，不依赖侧栏项目继续存在。

## 工作区标签

标签资源使用通用 `WorkspaceTab` 联合类型，不绑定到 PowerShell 或字符终端。工作区布局是由 `pane` 和 `split` 组成的递归树：叶子分区维护自己的标签顺序和活动标签，分支节点只描述左右或上下等分。拖动标签时根据叶子分区的实际屏幕边界判断落点：内容区左右约三分之一生成左右分屏，上下约四分之一生成上下分屏，标签栏本身只负责标签归组，避免误触分屏。标签随后从来源叶子分离并移动到目标叶子，或把目标叶子替换为新的分支，因此任意分区都能继续嵌套拆分。

本地终端、Telnet、串口与设置视图共用这一布局模型。协议生命周期仍然互相独立，分屏只改变视图归属，不重建正在运行的会话。

每个分区本身就是一个可见标签组，保留自己的标签顺序和活动标签；普通状态下所有标签位于同一组，瓷砖状态下 `Ctrl + Equal` 只重新排列已经打开的标签，不创建克隆会话或隐藏标签。整个工作区只维护一个当前活动分区。切换分区或标签时，标签栏会自动滚动到对应标签；视觉上使用安静的标签底色表达“本分区可见”，仅用一条轻量强调线表达“全局正在输入”，避免多个完整边框同时争夺注意力。

## 快捷键与同步输入

快捷键保存为“工作台命令 → 组合键”的用户设置，由工作台捕获并分派，终端组件不直接理解具体组合键。默认同步快捷键使用 `Ctrl+Alt+I` / `Ctrl+Alt+Shift+I`，避免抢占防火墙、Shell 和终端程序常用的 `Ctrl+A–Z` 控制输入；用户仍可自定义，设置页会提示潜在覆盖。字符终端向输入路由器注册各自的写入与聚焦能力；同步输入开启后，路由器只向递归布局中每个分区当前可见的本地终端、Telnet 或串口标签广播数据，设置页和隐藏标签不参与。关闭同步时，路由器将输入焦点交还当前活动分区的终端。

瓷砖排列快捷键默认为 `Ctrl + Equal`，只重新排列当前已打开的会话；`Ctrl+-` 将布局合并回单一分区。

当前实现不创建隐藏克隆标签；同步输入只面向布局中各标签组当前可见的终端。

## 设置与布局

- `ApplicationSettings` 保存主题、终端字体、光标、缓冲、ANSI 配色以及终端突显集。突显集拥有稳定 ID、名称和有序规则，同一时间只有一个活动集；旧版单层规则在读取时迁移为一个集合。这些是用户设置，未来可导入、导出或同步。
- `WorkbenchPreferences` 保存侧栏开关和宽度。这些是当前设备、当前窗口的布局偏好。
- 持久化设置在进入 React 状态前会按字段校验和迁移，损坏或旧版本数据不会把非法值传给 xterm.js。
- 终端外观变更直接更新 xterm.js 渲染选项，不销毁或重建底层 PTY 会话。

## 演进原则

优先完成真实功能，再根据重复、耦合和性能证据提取抽象。不为尚未出现的协议或极端情况预先建立复杂框架。
